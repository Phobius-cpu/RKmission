## Source findings

- This commit adds two tabs, not Dungeon Map. Roller is the initial/default tab; active tab alpha is 1, inactive alpha 0.65. The host imposes a 630-unit minimum width; Roller Settings changes from a vertical 310-unit layout to two 310-unit columns. These are XML layout units before AO AutoScale, not guaranteed screenshot pixels.
- Switching removes/re-attaches the same view. ManagerLoot locates its controls inside `_managerView`, avoiding searches in the detached Roller subtree. `MainUI` guards against rebinding a valid existing ManagerLoot view.
- Host recreation resets ManagerLoot's window/view references. The next loot selection creates a new view and binds handlers. `Rules` is not cleared by this window lifecycle; `RefreshList` repopulates the new view.
- Recreated editor fields intentionally reset Min QL=1, Max QL=500, Quantity=999, Exact=false and One each=false. This is different from saved rule fields. Do not classify loss of an unsaved editor draft as loss of a saved rule.
- `/ManagerLoot` and `/rkm loot` select Loot after reopening, so their final visible tab should be Loot even though host creation initially defaults to Roller. `/rkm auto` reopens the host and also arms automation; it is not a UI-only command.
- Native AO `RemoveChild`/`AddChild`, detached-view lifetime and `FitToContents` behavior require live validation. Source wiring alone cannot certify handler survival or resizing.
- Persistence limitation worth observing: `SaveRules` depends on a valid host and its SaveAs/dropdown controls. This test verifies UI lifecycle persistence; it does not certify background rule-quantity saving while the window is closed.
